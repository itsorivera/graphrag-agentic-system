# Lecture 4: Quantization & Model Efficiency

## 1. The Retrieval Trade-off: Cost, Speed, and Quality

As RAG systems transition from prototypes to production, developers must navigate a fundamental "triathlon" of software trade-offs: **Cost**, **Speed**, and **Quality**. Once a system is evaluated and baseline configurations are established, optimization often revolves around **Quantization**.

## 2. What is Quantization?

Quantization is the process of compressing models (LLMs) and their outputs (embedding vectors) by replacing high-precision data types with lower-precision equivalents.

![Quantization Trade-off](/rag-lectures/assets/quantization-tradeoff.png)

_Source: [Retrieval-Augmented Generation by Zain Hasan - DeepLearning.AI](https://www.deeplearning.ai/courses/retrieval-augmented-generation/)_

- **High Fidelity**: Original models usually operate in 32-bit or 16-bit precision.
- **Compression**: Quantization maps these values into 8-bit, 4-bit, or even 1-bit formats.

![Image compression](/rag-lectures/assets/image-compression.png)
_Source: [Retrieval-Augmented Generation by Zain Hasan - DeepLearning.AI](https://www.deeplearning.ai/courses/retrieval-augmented-generation/)_

- **Analogy**: Like image compression (reducing 24-bit color depth to 6-bit), quantization shrinks memory footprints and accelerates computation with a marginal, often negligible, sacrifice in retrieval relevance.

## 3. LLM Parameter Quantization

Modern LLMs contain billions of parameters, each typically requiring **16 bits** of memory. This creates massive GPU requirements.

![LLM Parameters](/rag-lectures/assets/llm-parameters.png)
_Source: [Retrieval-Augmented Generation by Zain Hasan - DeepLearning.AI](https://www.deeplearning.ai/courses/retrieval-augmented-generation/)_

- **Objective**: Reduce 16-bit parameters to 8-bit or 4-bit.
- **Benefit**: Significantly lowers the GPU VRAM required to host the model.
- **Performance**: Benchmark drops are usually minor, making quantized models highly efficient for production inference.

## 4. Embedding Vector Quantization

Embedding vectors are typically high-dimensional (e.g., 768 or 1536 dimensions) using 32-bit floating point numbers. At scale (millions of documents), this requires gigabytes of expensive RAM for rapid search.

### Integer Quantization (8-bit)

Integer quantization replaces 32-bit floats with 8-bit integers, reducing the vector size by **4x**.

**How it works:**

![Integer Quantization](/rag-lectures/assets/integer-quantization.png)
_Source: [Retrieval-Augmented Generation by Zain Hasan - DeepLearning.AI](https://www.deeplearning.ai/courses/retrieval-augmented-generation/)_

1. **Range Identification**: Find the minimum and maximum values for each dimension in the corpus.
2. **Bucketization**: Divide that range into 256 equal sections (the capacity of 8 bits).
3. **Mapping**: Each original float is assigned the integer ID of the section it falls into.

> [!TIP]
> **Why it works**: By storing only the min value and section width, the system can approximate the original float accurately enough for similarity search. Benchmarks like **Recall@K** often drop by only a few percentage points while search speed increases dramatically.

## 5. Extreme Compression: Binary Quantization

Binary (or 1-bit) quantization compresses vectors by a factor of **32x**.

- **Mechanism**: Each dimension is reduced to a `1` (positive) or `0` (negative).
- **Trade-off**: Significant performance drop in base retrieval.
- **The Rescoring Pattern**:
  - Use 1-bit vectors for a ultra-fast "first pass" retrieval.
  - Retrieve a slightly larger candidate set (e.g., top 100).
  - Rescore only those 100 candidates using the original 32-bit vectors to restore precision.

## 6. Matryoshka Embedding Models

Inspired by Russian nesting dolls, **Matryoshka Embeddings** allow for dynamic fidelity.

![Matryoshka Embeddings](/rag-lectures/assets/matryoshka-embeddings.png)

_Source: [Generated by Gemini 3 Pro](https://gemini.google.com/)_

### Information Density Sorting

Unlike standard embeddings where variance is distributed across all dimensions, Matryoshka models are trained to concentrate information into the earlier dimensions.

- **Efficiency**: You can use only the first 100 dimensions of a 1000-dimensional vector and still capture the majority of the statistical variance.
- **Use Case**: Performs exceptionally well in dynamic environments where you need to switch between low-fidelity (fast) and high-fidelity (precise) representations without re-embedding the entire corpus.

---

**Key Takeaway**: Quantization is a "free lunch" in many production scenarios. Experimenting with 8-bit or 4-bit quantized LLMs and embedding models provides significant cost and performance gains with minimal impact on user-perceived quality.
